# 面向热管理试验台的轻量组态监控上位机 · 项目计划书（V1.1）

> 原题名：面向热管理试验台的轻量热工参数边缘网关与专用组态监控上位机
> 版本：V1.1（硬件受限修订版）｜修订日期：2026-11-12｜开发周期：2026.11.13 — 2027.01.31
> 修订依据：当前仅有 **STM32H7 核心板（STM32HCORE）一块**，无温度 / 压力 / 流量传感器，无信号调理板、无 24V 电源、无继电器与电磁阀、无水泵。原 V1.0 的"实物联调"验收项在当前条件下不可达。

---

## 0. V1.0 → V1.1 的核心变更

| 项 | V1.0 | V1.1（本次修订） |
|---|---|---|
| 开发顺序 | 上位机与下位机并行，12 月实物联调 | **上位机（C# WPF）独占前期主线**，下位机只做"最小可用虚拟网关" |
| 传感器 | 作为一期硬件清单 | **移出当前阶段**，改为后期接入的预留接口，本期用"合成信号"替代 |
| 下位机定位 | 完整边缘网关（ADC、定时器捕获、QSPI 缓存、联锁 DO） | **虚拟信号源 + Modbus 从站 + 通道描述表**（3 个功能，1~2 周可完成） |
| 验收方式 | 曲线连续、超限 DO 动作、断线补发 | **三级运行模式（M0/M1/M2）分级验收**，见第 3 节；本期只验收 M0、M1 |
| 风险重心 | 硬件稳定性 | **C# 工程能力**：异步、线程安全、组态引擎、MVVM 解耦 |
| 交付重点 | 上位机 + 固件 + 测试报告 | 上位机为主体，固件为辅助；**可复现的架构与代码质量**是主线 |

**修订动机（一句话）**：硬件缺位不该阻塞软件进度。把传感器抽象成"数据源"，用合成信号跑通全链路，等硬件到货只需替换数据源实现，上位机代码零改动——这既是工程能力，也是面试里最值钱的一段设计叙述。

## 1. 项目定位与目标

### 1.1 定位
面向液冷 / 换热 / 散热类科研试验台的**轻量专用组态监控软件**，不做通用全品类 SCADA；组态引擎只服务温度、压力、流量三类热工变量；通道数量、量程、阈值全部由**通道描述表**驱动，不写死在代码里。

### 1.2 本期目标（2027.01 前必须完成）
1. **可运行的 C# WPF 上位机**：串口通信、自适应变量池、拖拽组态画布、实时曲线、分级报警、工程 JSON 存取、SQLite 归档与 CSV 导出。
2. **内置设备模拟器（M0）**：无任何硬件即可完整调试上位机全部逻辑，并支持注入故障（超限、断线、乱帧、CRC 错）。
3. **H7 虚拟信号源固件（M1）**：板卡不接任何传感器，用软件合成温度/压力/流量曲线，通过 USB VCP 跑 Modbus-RTU 从站，向上位机上报通道描述表与实时值——**真实串口链路在环**。
4. **后期硬件接入预留**：寄存器映射、通道类型、驱动接口全部预留，硬件到货后只增加"采集任务"，不改协议、不改上位机。

### 1.3 明确不做（本期边界）
- 不做 PID / 闭环控制算法（液冷控温闭环属于后续独立课题，本期只做"监控 + 参数下发"）。
- 不做用户权限、报表打印、Web 发布、多语言。
- 不做运动控制（伺服/步进）——与上位机求职项目分开，避免范围膨胀。
- 不做 FatFS 文件系统、不做以太网 / TCP 组网。

## 2. 三级运行模式（本版最重要的结构设计）

| 模式 | 数据来源 | 需要硬件 | 用途 | 本期是否验收 |
|---|---|---|---|---|
| **M0 纯软件仿真** | 进程内 `SimulatorTagSource`（不经过串口，不做 Modbus 编码） | 无 | 日常开发、单元测试、UI 迭代 | ✅ 必须 |
| **M1 板卡虚拟信号源** | H7 合成信号 → USB VCP → Modbus-RTU → `ModbusTagSource` | 仅 H7 板 + USB 线 | 验证真实链路、时序、断线重连、CRC | ✅ 必须 |
| **M2 真实传感器** | PT100/NTC、压力变送器、涡轮流量计 | 传感器 + 调理板 + 24V | 实物试验 | ⬜ 后期（2027.02 起） |

> 实现要点：上位机只认 `ITagSource` 接口，M0 / M1 是两个实现类，切换只改配置项 `DataSource: "Simulator" | "Modbus"`。**这是整个项目的解耦主轴，任何 UI 层不得出现 `if (仿真模式)` 分支。**

## 5. 上位机详细设计

### 5.1 分层与文件组织
```
LiquidConfig.sln
├─ src/LiquidConfig.Core/          # net10.0，纯类库，零 WPF 依赖
│   ├─ Abstractions/               # ITransport, IModbusClient, ITagSource, ILogger
│   ├─ Models/                     # ChannelDesc, TagVariable, WidgetConfig, ProjectDocument
│   ├─ Protocol/                   # Crc16, RtuCodec, FloatCodec, RegisterMap
│   ├─ Services/                   # ModbusClient, PollScheduler, TagRepository,
│   │                              # ProjectSerializer, ArchiveService, ReplayService
│   └─ Simulator/                  # SimulatorTagSource, SignalGenerator, FaultInjector
├─ src/LiquidConfig.App/           # net10.0-windows，WPF
│   ├─ Views/  ViewModels/  Controls/  Behaviors/  Converters/
├─ tests/LiquidConfig.Core.Tests/  # xUnit
└─ docs/                           # 本计划书、AI 开发文档、架构图、测试记录
```

### 5.2 变量池（全项目的心脏）
- `ChannelDesc` 由网关上报，上位机不硬编码任何通道。
- `TagRepository` 内部用 `ConcurrentDictionary<int, TagVariable>` 存值，UI 绑定用 `ObservableCollection<TagVariable>`（仅结构变化时增删，值变化走属性通知）。
- 采集线程（后台 `Task` 循环）只写字典；**UI 刷新走一个 200 ms 定时器批量派发**，避免 20 Hz 轮询把 UI 线程打爆。
- 每个 Tag 带质量位：`Good / AlarmHigh / AlarmLow / CommLost / Invalid`，断线时全通道置 `CommLost` 并保留最后值 + 时间戳（显示变灰），不允许清零冒充正常。

### 5.3 组态引擎（3 类热工控件）
1. **热工数字仪表**：绑定单个 Tag，显示数值 + 单位 + 质量色（正常深灰、警告橙、故障红、断线灰）。
2. **趋势曲线**：绑定 1~4 个 Tag，ScottPlot 承载，游标 / 缩放 / 暂停 / 时间窗切换（5 min / 30 min / 自定义）。
3. **报警指示灯**：绑定单通道，反映 `alarmFlags` 位；点击可跳转报警详情。

画布能力：拖拽移动、8 px 网格吸附、选中高亮（Adorner）、Delete 删除、右键改属性（右侧属性面板）、画布缩放（Ctrl+滚轮）、平移（空格+拖动）。全部用 WPF 原生（`Canvas` + 自定义 `FrameworkElement` + `OnRender`），**第一版不引入 SkiaSharp**。

> SkiaSharp 保留为 P2 可选优化项：仅当控件数量 > 200 或帧率不足时才切换；此时只替换 `IWidgetRenderer` 实现，不动数据与序列化。

### 5.4 组态工程文件（`.lcproj`，JSON）
```json
{
  "schemaVersion": 1,
  "canvas": { "width": 1200, "height": 700, "gridSize": 8 },
  "communication": { "mode": "Simulator", "port": "COM7", "baud": 115200, "slaveId": 1 },
  "widgets": [
    { "id": "w1", "type": "DigitalGauge", "tagId": 0, "x": 100, "y": 80, "w": 180, "h": 120, "unitOverride": null },
    { "id": "w2", "type": "AlarmLamp",  "tagId": 1, "x": 100, "y": 220, "w": 60,  "h": 60 },
    { "id": "w3", "type": "TrendPlot",  "tagIds": [0,1,2], "x": 320, "y": 80, "w": 620, "h": 340, "timeWindowMin": 30 }
  ]
}
```
关键约定：工程里**只存 `tagId`**，Tag 的语义（类型、单位、量程、阈值）永远来自网关；网关不接、通道被删，控件自动降级为"未绑定 / 断线"，工程不报错、不丢。

### 5.5 通信与容错
- 轮询调度：实时区 200 ms；报警区 2 s；设备状态 1 s；首连一次性读通道表。
- 超时 200 ms，重试 2 次，连续 5 次失败 → 状态机转 `Disconnected` → 指数退避重连（1s→2s→5s→10s 封顶）。
- 连接状态机：`Idle → Connecting → Online → Reconnecting → Fault`，UI 顶部状态条实时显示，不弹模态框。
- 报文调试窗口：环形缓冲 5000 条，显示时间、方向、地址、功能码、数据、CRC、耗时；可一键导出 txt 用于排查。

### 5.6 归档与导出
- SQLite 单表 `samples(ts INTEGER, tag_id INTEGER, value REAL, quality INTEGER)`，索引 `(ts, tag_id)`；批量插入（每 5 s 或 500 条 flush 一次），不逐条 commit。
- CSV 导出：宽表（时间 + 每通道一列），UTF-8 BOM + 逗号分隔，直接可被 Origin / Pandas 读。
- 历史回放：按时间范围读库，喂给曲线控件（不经过通信层），速率可调 1×/10×/50×。

## 6. 下位机（H7）本期范围：最小虚拟网关

> 定位：**不是产品，是"可编程信号源 + 协议对端"**。目标 1~2 周完成，之后不再动固件，把时间全留给 C#。

### 6.1 功能
1. **USB VCP**：CubeMX 开 `USB_OTG_FS` + `Middleware: USB Device (CDC/VCP)`，与 PC 枚举为虚拟串口。
2. **Modbus-RTU 从站**：字节流解析 → 地址过滤 → 功能码 `0x03/0x06/0x10` → CRC 校验（失败静默丢弃，不回应）→ 回帧。
3. **寄存器映射**：4 个功能区（设备信息 / 通道元描述 / 实时值 / 控制），地址表见开发文档第 6 节。
4. **通道描述表**：RAM 里默认 4 通道（2 温度 + 1 压力 + 1 流量），可在控制区下发修改；本期 Flash 持久化可先跳过（掉电恢复默认即可），标为 TBD。
5. **合成信号引擎**：每通道按 `simMode` 生成值：
   - `Static`：常数；
   - `Sine`：`base + amp·sin(2πt/T)`；
   - `Ramp`：`base + slope·t`，到上限折返；
   - `Step`：定时阶跃（用于测报警）；
   - `Fault`：注入卡死值 / 恒超限 / 停更（质量位置 `Invalid`）。
6. **看门狗 + 心跳指示**：板载 LED 1 Hz 翻转，表示主循环在跑（不用逻辑分析仪也知道固件活着）。

### 6.2 本期不做（后期恢复）
ADC 采集、TIM 输入捕获、工程量换算（本期值已是工程量）、本地超限联锁与 DO、QSPI 环形缓存与补发、FreeRTOS 多任务。后期只需要在"合成信号引擎"旁边并联一个"真实采集任务"，`ITagSource` 和寄存器映射完全不变。

## 8. 风险与对策

| 风险 | 表现 | 对策 |
|---|---|---|
| 画布拖拽踩坑（事件路由、坐标系、Adorner） | 卡住一周，进度崩 | P0 阶段先做 30 分钟 Spike：一个矩形能被拖动即可，跑通再扩控件 |
| 串口异步 + UI 线程混乱 | 界面假死、跨线程异常 | 铁律：通信全部后台 Task；写 UI 只通过 `Dispatcher.BeginInvoke` + 批量刷新 |
| VCP 枚举不稳定（Windows 与 H7 时钟/描述符配置） | 设备管理器出现又消失 | 先跑 CubeMX 默认 VCP 例程确认枚举，再改；不要在 USB 没通时写 Modbus |
| Modbus 浮点字序不一致 | 数值显示成 3.4e38 | `FloatCodec` 内置 `WordOrder` 配置项，M0/M1 均先做字序自检（发一拍已知值回读比对） |
